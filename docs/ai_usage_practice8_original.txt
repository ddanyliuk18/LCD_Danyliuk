TASK 1 — CALLABLE OBJECTS (1 POINT)
A struct that declares a member function named call can be called like a function: triple(14) means
triple.call(14). The longer form stays legal.
struct Scale
{
 i32 k
 fn call := (i32 v) -> i32
 {
 i32 r{v * k}
 exit r
 }
}
struct Counter
{
 i32 mut n
 fn call := () -> i32
 {
 n := n + 1
 exit n
 }
}
struct Shape
{
 Scale scale
 i32 side
 fn grown := () -> i32
 {
 i32 g{scale(side)}
 exit g
 }
}
Scale triple{3}
Counter mut c{0}
Shape s{{2}, 5}
print(triple(14))
print(triple.call(14))
print(s.scale(7))
print(s.grown())
i32 a{c()}
i32 b{c()}
print(c)
i32 r{a * 10 + b}
exit r
Expected output:
42
42
14
10
Counter{n: 2}
Program exit with result 12
scale is a field of Shape, so s.scale(7) is s.scale.call(7); inside grown, scale(side) calls the field of
its own object. The call of Counter changes n, so it is a mutating member function and the mutation rule holds
as for any other: with Counter c{0} the call c() is an error.
The call rule. For a name followed by (:
1. If the name is a variable visible here (a parameter, a local, a field inside a member function, a capture inside a
lambda), its type must be a struct that declares call. The call is name.call(args).
2. Otherwise the name is a function, found as before: a member function of the current struct, then a global
function.
3. Otherwise it is an unknown function.
1
If the name is both a visible variable and a function, the call is an error at the name: 'twice' is both a variable
and a function: rename one of them. Declaring both is allowed; only a call twice(…) is refused. The same
rule works after a dot: in obj.name(args), if name is a field of obj, the call is obj.name.call(args).
The rewrite. The parser cannot tell a variable from a function: triple(14) is a Call in --ast. The semantic
pass knows the names, so it makes the decision there and puts a member call in place of the call: the target triple,
the member function call, the same arguments. That member call is checked by the code that already checks
member calls (the arguments, the mutation rule), and code generation does not change. The IR of triple(14) and
of triple.call(14) is the same line:
%"call.ret" = call i32 @"Scale_call"(%"Scale"* %"triple", i32 14)
Errors. Each one with line:column; the wording is yours:
• a variable whose struct has no call: 'p' is not callable: Point has no member function 'call';
a variable of a built-in type: 'n' is not callable: it is i32;
• a name that is both a variable and a function, at the call;
• a wrong number or type of arguments (the message names the object, not call);
• a mutating call on a const object or through a const field: cannot call 'c': its 'call' changes it,
and it is not mut.
TASK 2 — LAMBDAS (1.5 POINTS)
A lambda is a function declared where a statement stands. The list in brackets names the variables it takes with it,
its captures:
statement ::= decl | assign | if | while | print | lambda
lambda ::= "fn" ident ":=" "[" [ ident { "," ident } ] "]"
 "(" [ type ident { "," type ident } ] ")" "->" type NL block
A lambda stands at the top level among the statements and inside any block: a function, a member function, if,
while, another lambda. A line that starts with fn name := [ is a lambda; fn without [ inside a block stays an
error, and so does a capture list on a member function.
• A capture is a copy taken at the declaration. Changing the variable later does not change the lambda. A
lambda declared inside a loop takes the current value on every iteration. Inside the body a capture is const.
• The body sees its parameters, its locals, its captures and the global functions. Nothing else: not the toplevel variables, not the locals and parameters of the enclosing function, not the fields of the enclosing struct,
unless they are captured. This is the same rule as for a function body, which does not see the top-level variables
either. A lambda cannot call itself: its name is declared after its body. A lambda may capture another lambda.
fn sq := (i32 v) -> i32
{
 i32 r{v * v}
 exit r
}
fn sum_scaled := (i32 factor, i32 a, i32 b) -> i32
{
 fn times := [factor](i32 v) -> i32
 {
 i32 r{factor * sq(v)}
 exit r
 }
 i32 s{times(a) + times(b)}
 exit s
}
i32 mut k{10}
fn add_k := [k](i32 y) -> i32
{
 i32 r{k + y}
 exit r
}
k := 100
print(add_k(5))
print(k)
print(sum_scaled(2, 3, 4))
exit add_k(1)
Expected output:
15
100
50
Program exit with result 11
add_k keeps the 10 it took at its declaration; times captures the parameter factor and calls the global function sq.
The rewrite. A lambda becomes three things the compiler already has:
1. a struct with one field per capture, of the type of the captured variable. The struct has no name in the language;
call it lambda.add_k in the compiler: a dot cannot appear in a name a program declares, so it never clashes2. its member function call with the parameters, the return type and the body of the lambda;
3. a variable add_k of that struct, initialised at this point with the captured values, as lambda.add_k add_k{k}.
After that, add_k(5) is a callable object from Task 1. Do the rewrite in the semantic pass: the types of the captures
are known only there. --ast stays the parse tree; add the flag --ast-checked, which prints the tree after the
semantic pass. A part of it for the program above:

In the IR the struct is a type, call is a member function with the object as its first parameter, and the declaration
is an alloca, a gep and a store per capture. A part of output.ll:
%"lambda.add_k" = type {i32}
define i32 @"lambda.add_k_call"(%"lambda.add_k"* %"this", i32 %"y")
...
 %"add_k" = alloca %"lambda.add_k"
 ...
 %"k.val" = load i32, i32* %"k"
 %"add_k.0.ptr" = getelementptr inbounds %"lambda.add_k", %"lambda.add_k"* %"add_k", i32 0, i32 0
 store i32 %"k.val", i32* %"add_k.0.ptr"
 store i32 100, i32* %"k"
 %"call.ret" = call i32 @"lambda.add_k_call"(%"lambda.add_k"* %"add_k", i32 5)
k := 100 is a store into k; the copy inside add_k stays 10.
The type has no name. So no parameter, return type, variable or field can have it. A lambda cannot be passed as
an argument, cannot be the value of exit, cannot initialise a declared variable or a field, cannot be assigned, and
cannot be printed. Its captures are not visible outside its body: add_k.k is an error.

ADDITIONAL TASK — MUT CAPTURES (+1)
[mut n] gives the lambda its own mutable copy of n: the field of the struct is mut. A call that assigns a mut
capture is a mutating member function, so the mutation rule decides where it may be called. The closure variable
is mut when one of its captures is mut, so a call like next() works at the place of the declaration. A capture of
another lambda is const unless it is written [mut next]. The original variable never changes, and a mut capture
of a const variable is allowed: it is a copy.
i32 n{0}
fn next := [mut n]() -> i32
{
 n := n + 1
 exit n
}
print(next())
print(next())
fn twice := [mut next]() -> i32
{
 i32 a{next()}
 i32 b{next()}
 i32 r{a * 10 + b}
 exit r
}
print(twice())
print(next())
exit n
Expected output:
1
2
34
3
Program exit with result 0
twice takes a copy of next whose counter is 2 and counts on that copy; the original next goes on from 2; n is
still 0. With [next] instead of [mut next] the copy is const, and the call inside twice is an error: line 11:11:
cannot call 'next': its 'call' changes it, and it is not mut. Add tests: a counter, a mut capture
changed in a loop, two lambdas with their own copies of one variable, a const and a mut capture in one list, and
the error above.
